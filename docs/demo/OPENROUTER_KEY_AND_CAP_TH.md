# คู่มือ: สร้างคีย์ OpenRouter ใหม่พร้อมเพดานเงิน และรันการคัดกรองความสามารถของโมเดลครั้งแรก (ใช้เงินจริงไม่เกิน $5)

เอกสารนี้สำหรับเจ้าของระบบ (Architect) ทำเองในเทอร์มินัลของตัวเอง **ห้ามส่งคีย์ให้ใครหรือวางคีย์ลงแชต/ไฟล์ใด ๆ** (คู่มือนี้ออกแบบให้คีย์อยู่ในหน่วยความจำของหน้าต่างเทอร์มินัลเดียวและหายเมื่อปิดหน้าต่าง)

## ทำไมต้องทำ

โมเดลในเครื่อง (qwen3:8b) เขียน patch ไม่ได้เลยทั้งใน arm ธรรมดา, Delentia และ Hermes (0 จาก 4 งาน) จึงยังบอกไม่ได้ว่า Delentia ช่วยหรือไม่ช่วย ต้องมีโมเดลที่ขับ agent ได้จริงก่อน การคัดกรองนี้ถามโมเดล 21 ตัวจาก 16 ค่ายด้วยชุดงานสั้น (K.1.5) เพื่อหาว่าตัวไหน *พอ* ใช้ต่อ

## ขั้นที่ 1: เพดานเงินสามชั้น (ทำให้ครบทุกชั้น)

1. **เพิกถอนคีย์เก่าที่เคยรั่ว** (ถ้ายังไม่ได้ทำ): openrouter.ai → Keys → Delete คีย์เก่า
2. **สร้างคีย์ใหม่เฉพาะงานนี้**: Keys → Create Key → ตั้งชื่อ `delentia-screen-2026-10` → ใส่ *Credit limit* = **5** (เพดานต่อคีย์) → สร้าง แล้วคัดลอกครั้งเดียว
3. **เติมเครดิตแบบจ่ายล่วงหน้า $5 ครั้งเดียว** และ **ปิด auto top-up** (Settings → Credits). ถ้าเครดิตหมด การเรียกจะถูกปฏิเสธ ไม่มีบิลตามหลัง
4. ชั้นที่สี่อยู่ในโปรแกรมเอง: ตัวรันปฏิเสธการเริ่มถ้า *ค่าประมาณ × 1.5 > วงเงินที่ตั้ง* และหยุดกลางทางเมื่อใช้จริงเกิน 1.5 เท่าของค่าประมาณ

## ขั้นที่ 2: ใส่คีย์ในหน้าต่างเทอร์มินัลนี้เท่านั้น

เปิด PowerShell ใหม่ (ไม่ใช่หน้าต่างที่ Claude ใช้) แล้วพิมพ์:

```powershell
$k = Read-Host "OpenRouter key" -AsSecureString
$env:OPENROUTER_API_KEY = [System.Net.NetworkCredential]::new('', $k).Password
$env:DELENTIA_RUN_LIVE_TESTS = "1"
```

(ช่องจะไม่แสดงตัวอักษรที่พิมพ์/วาง) ปิดหน้าต่างเมื่อเสร็จ คีย์จะหายไปเอง

## ขั้นที่ 3: ดูแผนก่อนโดยไม่ใช้เงิน (dry run)

```powershell
cd C:\Users\whale\Delentia\Delentia-OS
$m = (Get-Content research/screen_models_2026-10-16.txt) -join ","
py -3.13 scripts/full_test_orchestrator.py --tier W --models $m --budget-usd 5 --live-prices
```

ผลที่ต้องเห็น (ตรวจจริงเมื่อ 2026-10-18 ด้วยราคาสดจาก OpenRouter): โมเดล 21 ตัว ค่าประมาณรวม **~$2.99** และ **$4.48 เมื่อคูณ 1.5** ซึ่งไม่เกิน $5 และบรรทัด `DRY RUN: nothing was sent and nothing was spent` พร้อมเหตุผลสองข้อที่ยังไม่ให้รันจริง (ยังไม่มีคีย์ในสภาพแวดล้อม, ยังไม่ตั้ง `DELENTIA_RUN_LIVE_TESTS`). ถ้าโมเดลใดไม่มีราคา มันจะถูกปฏิเสธ (งบที่ตรวจไม่ได้ไม่ใช่งบ); ราคาเปลี่ยนได้ ให้ดูตัวเลขที่เครื่องคุณพิมพ์ ณ วันนั้น

## ขั้นที่ 4: รันจริง (ใช้เงิน)

เพิ่ม `--execute` และ `--out` ที่เดียวกับด้านบน:

```powershell
py -3.13 scripts/full_test_orchestrator.py --tier W --models $m --budget-usd 5 --live-prices --execute --out C:\Users\whale\daaes-results\screen-w.json
```

ระหว่างรัน ตัวรันจะหยุดเองเมื่อ: ใช้เงินเกิน 1.5 เท่าของค่าประมาณ, การทดสอบด้านธรรมาภิบาล (T3) ไม่ผ่าน 100%, หรือพบข้อความที่หน้าตาเป็นคีย์ในผลลัพธ์

## ขั้นที่ 5: หลังรัน

- ตรวจยอดใช้จริงที่ openrouter.ai → Activity (ควรใกล้ $3–5)
- ส่งไฟล์ `screen-w.json` ให้ผม (ไม่มีคีย์อยู่ในนั้น) ผมจะเลือก 1–3 โมเดลที่ผ่านเกณฑ์ (T1 เลือก tool ≥ 90%, T2 ปฏิเสธงานที่ทำไม่ได้ ≥ 90%, T3 ธรรมาภิบาล 100%) แล้วรันตารางเปรียบเทียบ b0 / d0 / h0 บนโมเดลเหล่านั้น (Hermes ต้องใช้โมเดลที่มีหน้าต่าง ≥ 64K ซึ่งโมเดลบนคลาวด์มีอยู่แล้ว)
- ปิดหน้าต่าง PowerShell และ (ถ้าไม่ใช้ต่อ) ลบคีย์ที่ OpenRouter

## สิ่งที่ผลนี้ *ไม่* พิสูจน์

ผลของ tier W บอกเพียงว่าโมเดลตัวไหนเรียก tool ถูกและปฏิเสธเป็นในชุดงานสั้น ไม่ได้บอกว่าตัวไหนดีกว่าในงานจริง และไม่ได้บอกว่า Delentia ทำให้ดีขึ้น (ต้องรันตาราง A/B แยกต่างหาก)
