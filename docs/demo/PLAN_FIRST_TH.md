# ยืนยันเป็นแผนก่อนลงมือ (plan-first) — คู่มือสำหรับเจ้าของ

ปกติระบบหยุดถามลายเซ็น "ทีละการกระทำ" ตามกฎในนโยบายของคุณ plan-first เพิ่มอีกแบบหนึ่ง: สำหรับ **ชนิดของการกระทำที่คุณเลือก** เอเจนต์จะไม่รันทันที แต่จดเป็นขั้นที่ 1, 2, 3 ของ **แผนเดียว** แล้วรอให้คุณยืนยันทั้งแผน **ครั้งเดียว**

## ทำงานอย่างไร

1. คุณสั่งงาน เช่น "ลบงานเก่า job-7 แล้วแก้ไฟล์ docs/notes.md"
2. เอเจนต์อ่าน/ค้นหาได้ตามปกติ แต่เมื่อขอการกระทำชนิดที่คุณเลือก ระบบตอบกลับว่า "proposed" (จดไว้แล้ว ยังไม่ได้รัน)
3. จบ episode ระบบรวมขั้นที่จดไว้เป็นแผนเดียว (มีเลขขั้น ชนิด และอาร์กิวเมนต์ทุกตัว) ขึ้นหน้า **Approvals** ในสถานะรอ
4. คุณเซ็นตามขั้นตอนปกติ (`delentia approvals sign ...` แล้ววาง JSON) แล้วกด Run — ลายเซ็นเดียวรันเฉพาะขั้นที่อยู่ในแผน ตามลำดับ ตรงตามไบต์
5. ก่อนรันทุกขั้น ระบบตรวจซ้ำด้วยกฎที่ลายเซ็นยกเลิกไม่ได้ (พื้นกฎของ shell, path ต้องห้าม, blocked patterns, การพักระบบ) ขั้นไหนล้มเหลวหรือถูกปฏิเสธ **ขั้นถัดไปไม่รัน**
6. ถ้าแผนถูกแก้ในฐานข้อมูล, นโยบายเปลี่ยน หรืออยู่คนละโฟลเดอร์งาน ระบบปฏิเสธและไม่รันอะไรเลย

## เปิดใช้

ที่ Desk หน้า **FDIA / Policy** มีกล่อง "ยืนยันเป็นแผนก่อนลงมือ" ติ๊กชนิดที่ต้องการ แล้วบันทึก หรือแก้ไฟล์นโยบายตรงๆ:

```json
{
  "plan_first": ["delete", "outward", "money", "permissions", "publish", "restore_cancel", "move_shutdown"],
  "small_edit_autorun": false
}
```

ชนิดที่มี: `delete` ลบ, `outward` ส่งออกนอก, `money` เงิน, `permissions` สิทธิ์/ผู้ใช้, `publish` เผยแพร่, `restore_cancel` ยกเลิก/กู้คืน/ย้อนกลับ, `move_shutdown` ย้าย/ปิดระบบ, `document_edit` แก้เอกสาร

ค่าเริ่มต้น: ว่าง (ไม่มีอะไรเปลี่ยน) ไม่มีชนิดไหนถูกเปิดให้จนกว่าคุณจะเลือก

## แก้ไฟล์เล็กที่ระบุชื่อ รันได้โดยไม่ต้องเซ็น (`small_edit_autorun`)

ปิดไว้เป็นค่าเริ่มต้น เมื่อเปิด การเขียน/แก้ **ไฟล์เดียว** ที่คำขอของคุณระบุชื่อเอง (เช่น "แก้คำผิดใน docs/notes.md") จะรันโดยไม่ต้องเซ็น ต่อเมื่อครบทุกข้อ: ไฟล์อยู่ในโฟลเดอร์งาน, ไม่ใช่ไฟล์ลับ (`.env` ฯลฯ), ใน episode นั้นยังไม่ได้อ่านข้อความจากภายนอก (เว็บ/อีเมล/ไฟล์ที่ส่งมา), และ checkpoint เปิดอยู่เพื่อย้อนกลับได้ (`delentia checkpoints`) ทุกการปฏิเสธอื่น (path ต้องห้าม, FDIA, hook) ยังคงอยู่ การเปิดข้อนี้ถูกบันทึกในประวัตินโยบายว่าเป็นการผ่อนกฎ ถ้าอยากให้ต้องเซ็นตอนแก้นโยบาย ให้ตั้ง `DELENTIA_POLICY_CHANGE_REQUIRES_SIGNATURE=1` บนโฮสต์

## ระบบเสนอให้ถามน้อยลง (Q3)

```bash
delentia approvals suggest
```

แสดงชนิดของการกระทำที่คุณอนุมัติและรันสำเร็จซ้ำ ≥ 5 ครั้งโดยไม่เคยปฏิเสธหรือล้มเหลว **เสนออย่างเดียว ไม่เปลี่ยนอะไร** และเสนอเฉพาะ "แก้เอกสาร" (ย้อนกลับได้ด้วย checkpoint) ส่วนลบ/เงิน/สิทธิ์/เผยแพร่/ส่งออก ระบบจะบอกว่าทำไมไม่เสนอ ไม่ว่าจะอนุมัติกี่ครั้ง

## ข้อจำกัดที่ต้องรู้

* ชนิดของคำสั่ง shell และเครื่องมือภายนอกอ่านจากถ้อยคำ (เป็นการประมาณ) การกระทำที่จัดชนิดไม่ได้ จะกลับไปใช้ประตูทีละการกระทำตามเดิม ไม่ถูกปล่อย
* ระบบนี้ไม่มีเครื่องมือส่งข้อความหรือจ่ายเงิน ชนิด `money`/`outward` จึงครอบคลุมเฉพาะเครื่องมือภายนอกที่คุณต่อเข้ามา — งานที่ต้องการ "ร่างให้คนส่งเอง" ให้บันทึกเป็นไฟล์แล้วส่งด้วยมือ
* แผนคือสิ่งที่โมเดลขอ ไม่ใช่การรับรองผลในโลกจริง ขั้นที่ขึ้นกับผลของขั้นก่อนจะไม่ถูกวางแผนใหม่ (การรันหยุดที่ขั้นแรกที่ล้มเหลว)
* ช่องแชต (Telegram/LINE ฯลฯ) ได้รับคำถามเมื่อ episode หยุด ไม่ได้เห็นแผนก่อนเครื่องมือแรก
