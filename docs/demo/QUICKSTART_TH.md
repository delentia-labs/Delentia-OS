# เริ่มใช้ Delentia ด้วยตัวเองใน 15 นาที (เดโมภาษาไทย)

สถานะ: **ทดลอง (experimental)** เดโมนี้พิสูจน์เส้นทาง "สั่งงานภาษาไทย → agent ใช้เครื่องมือจริงกับโฟลเดอร์จริง → ได้ไฟล์ผล → ตรวจผล → ปิดแล้วเปิดใหม่ยังจำได้"
ไม่ใช่การรับรองว่า agent ทำงานได้ทุกอย่าง และไม่ใช่ผล benchmark ของโมเดลใด

## ต้องมี

- Windows + Python 3.10 ขึ้นไป และโปรเจกต์ `Delentia-OS` ที่ติดตั้ง dependency แล้ว
- โมเดลที่ **เรียกเครื่องมือได้จริง** (ดูหัวข้อ "เลือกโมเดล") โมเดลที่ตอบแชทได้ไม่ได้แปลว่าเรียกเครื่องมือได้

## ขั้นตอน (ทำจากโฟลเดอร์ `Delentia-OS` หรือดับเบิลคลิก `RUN_DELENTIA_DEMO.bat` ที่โฟลเดอร์ Delentia)

```bash
python -m rct_control_plane.cli model show
python -m rct_control_plane.cli demo init
python -m rct_control_plane.cli demo run compare
```

1. `model show` บอกว่าจะใช้โมเดลไหน ถ้ามีคำเตือนเรื่อง key ให้ตั้งตามหัวข้อถัดไปก่อน
2. `demo init` สร้างโฟลเดอร์ `~/delentia-demo` พร้อมใบเสนอราคาสังเคราะห์ 3 ใบ (ไม่มีข้อมูลส่วนตัว) ไม่เขียนทับของเดิม
3. `demo run compare` สั่ง agent: อ่านใบเสนอราคา ทำตารางเทียบ สรุปเจ้าที่ไม่เกินงบ 15,000 บาท ห้ามแก้ไฟล์ต้นฉบับ ห้ามส่งข้อมูลออก

หน้าจอและไฟล์ `~/delentia-demo/results/<เวลา>-compare-….md` จะบอก 7 อย่าง: สถานะ, agent เรียกเครื่องมืออะไรบ้าง, ประตู FDIA ตัดสินอย่างไร,
อ่านข้อความจากภายนอกหรือไม่ (taint), คำตอบ, **ผลตรวจคำตอบกับเฉลยที่รู้อยู่แล้ว** (ไม่ใช่การตรวจของ agent เอง), และ audit chain ครบสมบูรณ์หรือไม่
ถ้าตรวจไม่ผ่านคำสั่งจะจบด้วยรหัส 1 และไฟล์ผลบอกข้อที่ไม่ผ่าน เดโมนี้รายงานความล้มเหลวตามจริงเสมอ

## ลองให้ครบทั้ง 5 กรณี

| คำสั่ง | สิ่งที่ควรเห็น |
|---|---|
| `demo run compare` | อ่านไฟล์ครบ 3 ใบ ตอบว่า สยามแอร์ และ บางกอกเทคนิค ไม่เกินงบ ไทยคูลลิ่งเกิน ไฟล์ต้นฉบับไม่เปลี่ยน |
| `demo run edit` | **หยุดรอลายเซ็น** ไฟล์ยังไม่เปลี่ยน แล้วพิมพ์รหัส; `demo approve <รหัส>` จึงแก้ได้ (ใช้ได้ครั้งเดียว) |
| `demo run remember` แล้วปิดหน้าต่าง เปิดใหม่ `demo run ask` | ตอบได้ว่าผู้อนุมัติงบคือคุณสมชายและต้องเรียงราคาต่ำไปสูง (ความจำอยู่ใน `data/`) |
| `demo run budget` | ใช้งบใหม่ 12,000 ไม่ใช่ 15,000 |
| `demo status` | โมเดล, รายการรออนุมัติ, จำนวนความจำ, audit chain |

กุญแจผู้อนุมัติของเดโมอยู่ในเครื่องเดียวกับ agent เพื่อให้เห็นขั้นตอนครบในที่เดียว **งานจริงต้องเซ็นจากอีกอุปกรณ์** (`delentia approvals sign`)

## เลือกโมเดล

ทดลองกับโมเดลในเครื่อง qwen2.5:7b (Ollama, CPU) เมื่อ 9 ต.ค. 2026: อ่านไฟล์ครบ 3 ใบได้ในบางรอบ แต่ตอบไม่ครบ/ตอบเป็นภาษาจีนในบางรอบ ยังไม่ผ่านเดโมนี้
ควรใช้โมเดลผ่าน OpenRouter ที่เรียกเครื่องมือได้ดี:

```bash
python -m rct_control_plane.cli model set <รหัสโมเดลจาก openrouter.ai/models> --provider openrouter
```

ตั้ง key ใน environment ของเครื่อง (ตัวแปร `OPENROUTER_API_KEY`) **อย่าพิมพ์ key ลงในไฟล์ แชท คลิป หรือ repository** แนะนำสร้าง key แยกสำหรับทดสอบและตั้งวงเงินต่ำ (เช่น 2–5 ดอลลาร์)
ที่หน้า OpenRouter ระบบมีเพดานต่อ episode อยู่แล้ว: `DELENTIA_EPISODE_BUDGET_USD`, `DELENTIA_EPISODE_MAX_TOKENS`, จำนวนขั้น (`--max-iterations`) และเวลา (`--max-seconds`)
และหยุดเองถ้าทำขั้นเดิมซ้ำ

**ต้นทุนต่อครั้ง:** เมนูเครื่องมือเต็ม (ค่าเริ่มต้น) ทำให้ prompt ราว 8,200 โทเคนต่อการเรียกโมเดลหนึ่งครั้ง (47 เครื่องมือ) จึงควรตั้งวงเงิน OpenRouter ต่ำไว้ก่อน
มีเมนูย่อให้เลือก (`DELENTIA_TOOL_MENU=ranked`, `DELENTIA_TOOL_MENU_FORMAT=compact`) ซึ่งลด prompt ต่อครั้งเหลือราว 1,500 โทเคน แต่ **ยังไม่ใช่ค่าเริ่มต้น**: ลองกับ qwen2.5:7b บนงานเทียบราคา 6 งานเดียวกัน
เมนูย่อทำให้โมเดลอ่านไฟล์ได้เพียง 1 จาก 6 รอบ จนพบและแก้ปัญหารูปแบบคำตอบสองแบบ (ใส่ชื่อ tool ในช่อง `action` / ส่งอาร์กิวเมนต์โดยไม่มีชื่อ tool) แล้วจึงอ่านได้ 6 จาก 6 เท่าเมนูเต็ม
(ผ่านตัวตรวจ 0 จาก 6 ทั้งสองแบบ) โมเดลเล็กตัวเดียว 6 งาน ยังไม่พอจะเปลี่ยนค่าเริ่มต้น ต้องรอทดสอบกับโมเดลที่เก่งเครื่องมือ

## ถ้าติดขัด

| อาการ | สาเหตุที่เจอ | ทางแก้ |
|---|---|---|
| `llm_error` | โมเดลไม่ตอบ | `model show`; ถ้าใช้ Ollama ตรวจว่าเปิดอยู่และมีโมเดลนั้น |
| ใช้เครื่องมือผิด / ตอบเป็นภาษาอื่น | โมเดลเล็กใช้ tool ไม่แม่น | เปลี่ยนโมเดล; ผลนี้ถูกต้องที่ระบบรายงานว่า "ไม่ผ่าน" |
| `max_iterations_reached` | งานต้องหลายขั้น | `--max-iterations 12` |
| `pending_approval` | ระบบรอลายเซ็น (พฤติกรรมที่ถูกต้อง) | `demo approve <รหัส>` |

## ขอบเขตที่ทดสอบแล้ว / ยังไม่ได้ทดสอบ

- ทดสอบแล้ว (โมเดลจำลองที่ทำตามสคริปต์ + เครื่องมือจริง + กระบวนการแยกกัน): init, compare, taint, edit→approve ใช้ซ้ำไม่ได้, ความจำข้ามการเปิดใหม่, ตัวตรวจเฉลย
- ทดสอบแล้วกับ qwen2.5:7b ในเครื่อง: รันได้ ปลอดภัย รายงานตามจริง แต่ **ไม่ผ่าน** เกณฑ์ตอบถูก
- **ยังไม่ได้ทดสอบ:** โมเดลที่เก่งเรื่องเครื่องมือ (OpenRouter) รันซ้ำ 3 ครั้งจากสถานะเริ่มต้น เจ้าของรันเอง ติดตั้งบนเครื่องสะอาด
