# ข้อมูลของคุณ: อยู่ที่ไหน สำรองอย่างไร ลบคนหนึ่งคนออกอย่างไร และถอนการติดตั้งแล้วอะไรหาย

Delentia ทำงานบนเครื่องของคุณและเก็บสิ่งที่รู้เกี่ยวกับคุณไว้ใน **โฟลเดอร์เดียวที่เป็นของคุณ** หน้านี้บอกว่าในนั้นมีอะไร คัดลอกไปเก็บให้ปลอดภัยอย่างไร ลบคนหนึ่งคนออกอย่างไร และการถอนการติดตั้งลบอะไรหรือไม่ลบอะไร ไม่มีขั้นตอนไหนต้องใช้อินเทอร์เน็ต

**สถานะตามจริง:** คำสั่งด้านล่างมีอยู่จริงและมีเทสต์อัตโนมัติครอบคลุม (สำรอง คืนค่า ลบ) การสำรองและคืนค่าถูกรันบนเครื่องผู้สร้างและใน CI แต่ **ยังไม่มีใครอื่นรันกับข้อมูลของตัวเอง** การลบทิ้งบางอย่างไว้ทั้งโดยตั้งใจและตามข้อจำกัดที่รู้อยู่ (ดูหัวข้อ "ลบคนหนึ่งคน") อ่านก่อนพึ่งพามัน

## ข้อมูลอยู่ที่ไหน

| คุณติดตั้งด้วย | โฟลเดอร์ข้อมูล |
|---|---|
| ตัวติดตั้ง Windows หรือ `pip install delentia-os` | `%USERPROFILE%\.delentia` (Linux และ macOS: `~/.delentia`) |
| ซอร์สโค้ด (นักพัฒนา) | โฟลเดอร์ของ repository เว้นแต่ตั้ง `DELENTIA_HOME` ไปที่อื่น |
| ทุกแบบข้างบนที่ตั้ง `DELENTIA_HOME` | โฟลเดอร์นั้นพอดี |

ข้างในโฟลเดอร์ (จะเห็นเฉพาะส่วนที่มีบนเครื่องคุณ):

| อะไร | คืออะไร |
|---|---|
| `agentic.db` | บันทึกว่าเอเจนต์ทำอะไรไปบ้าง (ห่วงโซ่ตรวจสอบที่ลงนามและเชื่อมกัน) การอนุมัติ และความจำ |
| `rct_control_plane.db` | ตารางชุดเดิมของระบบควบคุม (เช่น สกิลที่เอเจนต์เรียนรู้) |
| `keys\` | **กุญแจส่วนตัว** (กุญแจลงนามบันทึก กุญแจผู้อนุมัติ) ใครถือกุญแจส่วนตัวก็ลงนามแทนคุณได้ ห้ามส่งทางอีเมล ห้ามใส่ใน repository |
| `memory_keys\` | กุญแจหนึ่งดอกต่อหนึ่งคนที่ล็อกความจำของคนนั้น การทำลายกุญแจของใครคือวิธีลบคนนั้น |
| `approvers.json` | กุญแจสาธารณะของคนที่อนุมัติการกระทำได้ |
| `model.json` | โมเดลที่ Delentia ใช้ (ไม่เก็บคีย์) |
| `law_packs\` | กฎหมายที่คุณนำเข้าเอง |
| `logs\` และ `run\` | ไฟล์บันทึกและหมายเลขโปรเซส ที่ `delentia launch` เขียน |
| `browser_shots\` | ภาพที่เครื่องมือเบราว์เซอร์ถ่ายไว้ |

**การติดตั้ง อัปเดต และถอนการติดตั้ง ไม่แตะโฟลเดอร์นี้**

## สำรองข้อมูล

```
delentia backup create --out C:\Backups\delentia-2026-10-31.zip
delentia backup verify C:\Backups\delentia-2026-10-31.zip
```

* คัดลอกฐานข้อมูลด้วยการสำรองออนไลน์ของ SQLite เอง จึงปลอดภัยขณะ Delentia กำลังทำงาน และเพิ่มการตั้งค่า (`model.json`, `approvers.json`, นโยบาย, `AGENTS.md`/`SOUL.md` และที่คล้ายกัน) ทุกไฟล์มี SHA-256 ใน `manifest.json` ในซิป
* **กุญแจส่วนตัวถูกเว้นไว้** (ทุกอย่างใต้ `keys\`, ไฟล์ `.pem`, ไฟล์โทเค็น) ซิปที่คัดลอกขึ้นไดรฟ์คลาวด์จึงไม่ใช่ช่องทางทำกุญแจลงนามหาย ใส่ `--include-keys` เฉพาะเมื่อคุณตัดสินใจแล้วว่าซิปนั้นอ่อนไหวเท่ากุญแจ และเก็บไว้ในที่ที่คุณคุมได้ ถ้าไม่มีกุญแจ ข้อมูลที่คืนมายังแสดงประวัติได้ แต่ลงนามรายการใหม่ด้วยกุญแจเดิมไม่ได้ และ **ความจำที่ล็อกรายบุคคล (`memory_keys\`) อ่านกลับไม่ได้** ถ้าอยากกู้ความจำได้ ให้เก็บสำเนา `memory_keys\` แยกไว้ด้วยความระวังเท่ากุญแจ
* ไฟล์สำรองไม่ถูกเขียนทับ: ตั้งชื่อใหม่ทุกครั้ง
* `delentia backup verify` ตรวจทุกไฟล์กับ manifest อีกครั้ง ทำหนึ่งครั้งหลังสร้าง และอีกครั้งก่อนจะพึ่งพามัน

## คืนค่า

```
delentia backup restore C:\Backups\delentia-2026-10-31.zip --to C:\Restore
```

* ทุกอย่างถูกตรวจกับ manifest **ก่อน** เขียนอะไรลงดิสก์ ผิดหนึ่งไบต์ก็หยุดทั้งหมด
* ไฟล์ไปอยู่ใต้ `C:\Restore\home` (ฐานข้อมูล) และ `C:\Restore\user` (การตั้งค่า) คุณจึงดูก่อนได้ว่าจะคัดลอกทับของจริงหรือไม่
* ถ้ามีไฟล์อยู่แล้ว การคืนค่าจะปฏิเสธ ถ้าใส่ `--force` มันจะย้ายไฟล์เก่าไปเก็บ (ชื่อ `...before-restore-<เวลา>`) ไม่ลบทิ้ง
* ห่วงโซ่ตรวจสอบในฐานข้อมูลที่คืนมายังตรวจผ่าน เพราะเป็นไบต์เดียวกัน สิ่งที่เขียนหลังเวลาสำรองไม่อยู่ในนั้น

## ลบคนหนึ่งคน

ถ้าหลายคนใช้ Delentia เครื่องเดียวกัน (แต่ละคนมี namespace ของตัวเอง) คุณลบคนหนึ่งออกได้โดยไม่แตะคนอื่น ต้องมี **ลายเซ็นของผู้อนุมัติ** เพราะย้อนกลับไม่ได้

```
delentia memory erase-request <namespace>
delentia memory erase-sign <namespace> <head_hash> --approver-key <ไฟล์กุญแจผู้อนุมัติ>
delentia memory erase <namespace> --reason "<เหตุผล โดยไม่ใส่ข้อมูลส่วนบุคคล>" --public-key <กุญแจสาธารณะผู้อนุมัติ> --signature <ลายเซ็น> --confirm <namespace>
```

* `erase-request` พิมพ์สิ่งที่จะต้องลงนามและรายการว่าอะไรเก็บข้อความของคนนั้นอยู่ `erase-sign` รันบนอุปกรณ์ของผู้อนุมัติเอง `erase` ทำลายกุญแจความจำของคนนั้น ลบสำเนาที่อ่านได้ในตาราง และบีบไฟล์ฐานข้อมูลเพื่อไม่ให้ข้อความตกค้างในหน้าว่าง
* บันทึกที่ลงนามว่ามีการลบเกิดขึ้นยังอยู่ (ไม่มีข้อความส่วนบุคคลในนั้น) ห่วงโซ่ยังตรวจผ่าน
* **สิ่งที่การลบ *ไม่* ทำ (คำสั่งพิมพ์รายการนี้ตอนจบ):** แถวบันทึกที่เขียนก่อนมีฟีเจอร์นี้ไม่ได้ล็อกไว้ จึงรายงานไม่แก้ไข ฐานข้อมูลสกิลที่แยกอยู่ก็รายงาน ตารางอื่นที่มีชื่อคนนั้นถูกเขียนทับ แต่สำเนาข้อความธรรมดาที่อื่น (ไฟล์ที่คุณส่งออก ภาพหน้าจอ) คุณต้องตามหาเอง
* **ไฟล์สำรองที่ทำก่อนการลบยังมีคำพูดของคนนั้นอยู่** การลบจากโฟลเดอร์จริงไปไม่ถึงสำเนา รัน

  ```
  delentia backup erasure-check C:\Backups
  ```

  เพื่อดูว่าไฟล์สำรองไหนยังเก็บคนที่ถูกลบ (exit code 1 ถ้ามี) มันไม่ลบอะไร จะลบหรือแทนที่ไฟล์สำรองเก่าเป็นการตัดสินใจของคุณ

## เริ่มใหม่ด้วยไฟล์ตัวอย่าง

ถ้าต้องการแค่โฟลเดอร์เดโมกลับมาเหมือนเดิม:

```
delentia demo reset
```

คืนใบเสนอราคาตัวอย่างให้เหมือนที่ `delentia demo init` เขียน และเก็บสำเนาไฟล์ที่ถูกแก้ไว้ ไม่มีอะไรถูกลบ

## ถอนการติดตั้ง

* **ตัวติดตั้ง Windows:** Settings → Apps → Delentia → Uninstall หยุดสิ่งที่กำลังรันและลบ `%LOCALAPPDATA%\Programs\Delentia` **โฟลเดอร์ข้อมูลของคุณยังอยู่**
* **pip:** `pip uninstall delentia-os` โฟลเดอร์ข้อมูลยังอยู่
* ถ้าจะลบข้อมูลด้วย ให้ลบโฟลเดอร์ข้อมูลเอง **หลังจาก** สำรองไว้ถ้าอาจต้องการ การลบ `%USERPROFILE%\.delentia` ลบความจำ บันทึก กุญแจ และการตั้งค่าถาวร ย้อนกลับไม่ได้ และถ้าไม่มีกุญแจ ก็พิสูจน์ไม่ได้อีกว่าบันทึกเก่าเป็นของคุณ

## สิ่งที่ยังไม่มี

ใน Desk ยังไม่มีปุ่มสำรองหรือลบ ทั้งสองเป็นคำสั่ง ยังไม่มีการสำรองตามเวลา Delentia ไม่ส่งข้อมูลของคุณไปไหนเอง สิ่งที่ออกจากเครื่องคือข้อความของคำขอที่ส่งให้โมเดลที่ **คุณ** เลือก (ดูหน้า Models) และการตรวจเวอร์ชันวันละครั้งที่ไม่ส่งอะไรเกี่ยวกับคุณ (`delentia update --turn-off` ปิดได้)
