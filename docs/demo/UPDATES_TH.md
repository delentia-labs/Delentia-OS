# การแจ้งเตือนและติดตั้งเวอร์ชันใหม่

## สรุป

* Delentia **ตรวจเองว่ามีเวอร์ชันใหม่ไหม** วันละไม่เกินหนึ่งครั้ง และ **แจ้งเตือน** ที่หน้า สถานะ (แถบสีเขียว) และใน ตั้งค่า → เวอร์ชันและการอัปเดต
* การ **ติดตั้ง** ทำโดยคุณเท่านั้น: เมนู Start → **Update Delentia** หรือคำสั่ง `delentia update --apply` ระบบถามก่อนเสมอ
* ข้อมูลของคุณ (`%USERPROFILE%\.delentia`) ไม่ถูกแตะ

## การตรวจเวอร์ชันใหม่ทำงานอย่างไร

* ส่งคำขอเล็ก ๆ หนึ่งครั้งไปที่ `https://pypi.org/pypi/delentia-os/json` (ที่เก็บแพ็กเกจสาธารณะ) อ่านว่ารุ่นล่าสุดคืออะไร
* **ไม่ส่งข้อมูลของคุณ** เซิร์ฟเวอร์เห็นเฉพาะที่อยู่เครือข่ายของคุณและข้อความ `delentia-os/<เวอร์ชัน> update-check` ในส่วนหัวคำขอ เหมือนทุกครั้งที่ใครสักคนสั่ง `pip install`
* จำผลไว้ 24 ชั่วโมง (ไฟล์ `update_check.json` ในโฟลเดอร์ข้อมูลของคุณ) เปิดหน้าเว็บบ่อยแค่ไหนก็ไม่ยิงคำขอซ้ำ
* ถ้าเน็ตไม่มีหรือเซิร์ฟเวอร์ไม่ตอบ ผลคือ "ตรวจไม่ได้ตอนนี้" ไม่ใช่ข้อผิดพลาด และระบบเก็บผลล่าสุดที่รู้ไว้
* เปรียบเทียบเลขเวอร์ชันเอง รุ่นทดลอง (rc, a, b) ไม่ถูกเสนอให้คุณ

### ปิดการตรวจ
* หน้า ตั้งค่า → เวอร์ชันและการอัปเดต → **ปิดการตรวจรายวัน** หรือ
* `delentia update --turn-off` หรือตั้ง `DELENTIA_UPDATE_CHECK=off` หรือ `DELENTIA_OFFLINE=1` (เครื่องที่ห้ามต่อเน็ต)
* เปิดอีกครั้ง: `delentia update --turn-on`
* เมื่อปิดไว้ จะไม่มีคำขอออกไปเลยสักครั้ง (มีเทสต์ยืนยัน)

## ติดตั้งเวอร์ชันใหม่

1. ปิดเอเจนต์: เมนู Start → **Stop Delentia** (Windows แทนที่ไฟล์ที่กำลังใช้งานอยู่ไม่ได้ ระบบจึงไม่รีสตาร์ตให้เอง)
2. เมนู Start → **Update Delentia** (หรือพิมพ์ `delentia update --apply`)
3. หน้าต่างบอกว่ามีรุ่นอะไร และถามว่า "ติดตั้งตอนนี้ไหม" ตอบ `y`
4. ระบบทำตามลำดับ: ดาวน์โหลดไฟล์ของรุ่นนั้นอย่างเดียว → **ตรวจ SHA-256 ว่าตรงกับที่ที่เก็บแพ็กเกจประกาศไว้** → ถ้าตรงเท่านั้นจึงติดตั้ง → ถ้าไม่ตรงหยุดทันที ไม่ติดตั้งอะไร
5. เมนู Start → **Delentia** เพื่อเริ่มใหม่

อัปเดตแบบออฟไลน์: `delentia update --apply --find-links <โฟลเดอร์ที่มีไฟล์ .whl>` ติดตั้งจากไฟล์ที่ได้มาด้วยวิธีอื่น (ยังตรวจ SHA-256 กับค่าที่ประกาศ ซึ่งต้องเคยตรวจได้ตอนออนไลน์)

## ทำไมไม่มีปุ่ม "อัปเดตเลย" ในหน้าเว็บ

ผมตั้งใจไม่ทำ ด้วยเหตุผล 3 ข้อ:
1. การอัปเดตคือการ **แทนที่โปรแกรมที่กำลังทำงาน** บน Windows ไฟล์ที่ใช้งานอยู่แทนที่ไม่ได้ ต้องปิดก่อน หน้าเว็บที่ปิดโปรแกรมตัวเองแล้วอัปเดตแล้วเปิดใหม่เองเป็นงานเสี่ยงที่ต้องออกแบบเพิ่ม
2. การรันโค้ดที่ดาวน์โหลดมาเป็น "งานเสี่ยง" ตามนิยามของระบบนี้เอง ควรมีคนจริงยืนยัน ที่เทอร์มินัลที่คนนั่งอยู่หน้าเครื่อง ไม่ใช่ปุ่มที่โปรแกรมอื่นกดแทนได้
3. คำสั่งอัปเดตถูกบล็อกจากเอเจนต์สองชั้น (ตัวคำสั่งปฏิเสธเมื่อรู้ว่ามาจากเอเจนต์ และตัวคัดกรองคำสั่งปฏิเสธข้อความ `update --apply`) เอเจนต์ที่ถูกหลอกให้อัปเดตตัวเองจึงทำไม่ได้

ที่อยู่ในแผน (ยังไม่ทำ): ปุ่มในหน้าเว็บที่สร้างคำขออนุมัติ แล้วให้คุณยืนยันด้วย Windows Hello จากนั้นตัวช่วยแยกกระบวนการจะปิดโปรแกรม อัปเดต และเปิดใหม่ให้

## ข้อจำกัดของความน่าเชื่อถือ

SHA-256 ที่ตรวจมาจากที่เก็บแพ็กเกจเดียวกับไฟล์ จึงกันไฟล์เสียหรือถูกสลับระหว่างทาง แต่ **ไม่กันกรณีที่ที่เก็บแพ็กเกจเองถูกแฮ็ก** การเผยแพร่ใช้โทเค็นที่ผู้ดูแลถือและทำจากระบบ CI การเผยแพร่พร้อมหลักฐานที่มา (attestation) เป็นขั้นต่อไป

## คำสั่งทั้งหมด

| คำสั่ง | ทำอะไร |
|---|---|
| `delentia update` | ตรวจ (บังคับตรวจใหม่) แล้วบอกว่ามีรุ่นใหม่ไหม |
| `delentia update --apply` | ติดตั้งรุ่นใหม่ (ถามก่อน) |
| `delentia update --apply --yes` | ไม่ถาม (สำหรับสคริปต์ของคุณเอง) |
| `delentia update --turn-off` / `--turn-on` | ปิด/เปิดการตรวจรายวัน |
| `delentia update --apply --find-links <โฟลเดอร์>` | ติดตั้งจากไฟล์ในเครื่อง |
