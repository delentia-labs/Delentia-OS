# RCT-7: the definition, and what the runtime implements today

Re-checked on 2026-10-31 (round 107) by reading the code and running the tests named below; the model-assisted parts were added in round 98 and measured on holdouts labelled by the project owner in rounds 99 to 105. Thai summary at the end.

**RCT-7, Reverse Component Thinking**, is the creator's way of working in seven steps. The table separates the **requirement** (the creator's definition of each step) from the **implementation**. A step that is only partly implemented is not described as done anywhere else in this repository.

**Where the limit is.** Everything marked "by rule" reads the request's own words and tests the result without a language model: it cannot see what the words do not say. What needs a model that can read intent (unknowns the words do not show, a vague goal, a wrong-but-well-formed answer) is **not** done, and no held-out measurement with a capable model exists yet. The wait-and-ask behaviour is **on where a person is present** (the Desk and the chat channels) and **off where nobody is waiting** (jobs, schedules, webhooks, subagents, the HTTP API), because a question to nobody would sit until it expires. `DELENTIA_ASK_AND_WAIT=1` turns it on everywhere, `=off` nowhere. This default was set on 2026-10-24 on the strength of a false-stop measurement made on cases the rules' author wrote (1 false stop in 40); it has not yet been measured on real requests. The plan and the lists below are always produced.

| ID | Step | Requirement | What the runtime does today | Status |
|---|---|---|---|---|
| R1 | Observe | Collect what is known **and what is unknown** | Always lists two kinds of unknown, by rule: a file the request tells the agent to read or edit that exists nowhere in the workspace, and a bare reference ("fix it") with no earlier conversation. With the flag, the episode stops before the first model call and asks. Unknowns the words do not show are not found by rule. **Opt-in, off by default** (`DELENTIA_RCT7_JUDGE=propose`): a model proposes questions, each of which must cite words of the request (a question about something the request never mentions is dropped); it can only ask, never act. On the author's own 40 requests local 7-8B models found 18-20 of 20 with 0 false pauses; a 3B model found 10 of 20. On a holdout of 60 requests labelled by the project owner (not by the author of the rules), qwen3:8b found 0.85 of the requests that needed a question and paused on 0.16 of those that did not, against pass rules of at least 0.80 and at most 0.15 written beforehand: **not met, by one case**; qwen2.5:7b found 0.53. A later set of 60 new requests did not reproduce the one pass that an earlier two-axis set had shown for the variant that is given extra context (a pass at the edge of both bounds). No capable hosted model has been run | Partial (rules by default; model-proposed unknowns opt-in; the owner-labelled holdouts did not meet their pass rule with local models) |
| R2 | Analyze | Relations, constraints and ambiguities from the intent | Records intent type and scope; reads seven kinds of requirement from the request's own words (answer language, JSON format, a file to save, a file not to change, a word limit, a character limit, a list length) | Partial |
| R3 | Deconstruct | Components, dependencies, inputs and outputs | Splits only what the person wrote as separate steps (a numbered or bulleted list, "Step 1 … Step 2", "first … then …", Thai "แล้ว" / "จากนั้น"); anything else is one part. No dependency analysis outside an intent contract | Partial |
| R4 | Reverse reasoning | An inspectable chain from the wanted result back to the necessary conditions and the evidence or actions that support them | Shows, before the first tool, the conditions the result must satisfy (read from the request) with how each will be checked. Every finished episode also carries an evidence chain without a model: each number, file name or address of the answer traced to the step that returned it, to the request, or reported as found nowhere. **Opt-in** (`DELENTIA_RCT7_CHAIN=cite`): a model lists the answer's claims with a quote from a step; the code accepts a claim only if the quote occurs verbatim in that step, its numbers and names are covered, and every clause of the answer is covered by some claim. It is a chain over facts that have tokens or quotes, not over every kind of reasoning | Partial |
| R5 | Identify core intent | When the intent is not clear, **ask the user and wait** | A question store (sealed per person, survives a restart, answered once, the answer is a new intent version, the original is kept). The loop asks for the rule-visible unknowns above, and for a result that breaks a stated requirement. The answer attaches to the same request once, when the person sends it again; "accept" closes it without running anything. General "the intent is unclear" is the opt-in model proposal above, with a per-person brake: if most of what the model proposed to a person was dismissed, it stops proposing to them. Where nobody is waiting (jobs, schedules, webhooks, the HTTP API) the loop does not ask: it is off there by design, and a "park the question and tell the owner" state does not exist yet | Partial |
| R6 | Reconstruct | The user **sees the plan before** the real artifact is built | The plan, its conditions, parts and unknowns reach the Desk before the first tool and are in every result (`rct7_plan`). Chat channels do not get a plan before the first tool; they get the question when the episode stops to ask. Separately, **plan-first approval** (off until the owner's policy turns it on) turns the effects of eight action kinds (delete, send out, money, permissions, publish, restore or cancel, move or shut down, edit a document) into one numbered plan with one signature over its digest; nothing runs before that signature | Partial |
| R7 | Compare with intent | If the result does not match, **report the difference, stop and ask**, then analyse again with the answer | For the seven kinds above, a difference stops the episode with a question that states expected and observed; nothing is learned from it. The end-of-episode similarity/grounding check still only decides whether the episode may become a skill. **Opt-in** (`DELENTIA_RCT7_JUDGE=propose`): where the rules found no difference a model may judge that the answer misses a part of the request, and the part must be cited from the request; on the author's own 40 pairs 17-19 of 20 unmet answers were found with 0-1 false stops (7-8B models). On a holdout of 40 pairs labelled by the project owner, qwen3:8b found 6 of 8 unmet answers (the rule written beforehand asked for 7 of 8) with 0 of 24 false stops; qwen2.5:7b found 6 of 8 with 8 of 24 false stops: **neither met the rule** | Partial |

## What this does not say

- It does not say the runtime has no clarification anywhere else: the intent-contract path (`intent_contract.py`, `typed_intent.py`, `intent_conditions.py`, `intent_review.py`, `evidence_requirement.py`, `citation_verifier.py`, `citation_acquisition.py`) has its own questions, its own typed criteria and necessary conditions, and a citation verifier, and is separate from the loop described above. It is opt-in, covers a few task families, and is not yet reachable through a public route for general tasks. The two halves do not yet share one plan object; until they do, the same request can be analysed twice.
- The numbers above come from local 3B to 8B models on a CPU. **No capable hosted model has driven the runtime under test conditions, so nothing here says RCT-7 makes a good model better.** Completeness has three meanings (the structure exists; the judgement of unclear intent works; it measurably helps) and only the first is close.
- A "backward chain" means a plan structure that can be checked. It is not a claim about what happens inside a language model.
- Showing a plan does not mean every plan needs a new approval. Approvals follow the owner's policy and the risk of each action.
- A clarification answer is not an approval: it never lifts a gate, a forbidden path or a signature requirement.
- Measured only on cases written by the author of the rules (regression guards, not independent evidence): `research/rct7_round97_criteria.md` has the rules written before the code; `python -m research.rct7_round97_measure` reproduces the counts.

## Acceptance cases and where they are tested

RC01 an unknown that blocks the goal is asked about: `test_rct7_round97_real.py::test_a_missing_file_stops_before_the_first_model_call_and_asks` (a missing file only). RC02 not tested. RC03 and RC04 (a claim that the evidence does not support is reported, a faithful answer has no gaps): `test_rct7_round98_real.py::test_the_baseline_chain_traces_tokens_to_steps_the_request_or_nowhere`, `::test_a_claim_is_verified_only_when_its_quote_occurs_verbatim_in_the_cited_step`, `::test_a_clause_of_the_answer_that_no_listed_claim_speaks_about_is_reported_as_a_gap`, and for claims of an action `test_rct7_action_claims_round99_real.py`. RC05 ambiguous intent with two outcomes: not implemented (needs a model). RC06 the plan is shown before any effect: `test_ask_and_wait_loop_round96_real.py`. RC07 a wrong-language or wrong-format result is reported and paused: same file. RC08 a revised goal keeps the original: `test_clarifications_round92_real.py`, `test_rct7_round97_real.py`. RC09 a correct short answer is not stopped: `test_ask_and_wait_loop_round96_real.py`, `test_ask_and_wait_false_pause_round96_real.py`. RC10 a restart while waiting keeps the pending state: `test_clarifications_round92_real.py`.

## สรุปภาษาไทย

ตรวจใหม่รอบที่ 107 (31 ต.ค. 2026): ส่วนที่ใช้โมเดลช่วย (judge, critic, โซ่หลักฐาน) วัดแล้วกับชุดที่เจ้าของระบบติดป้ายเอง 4 ชุด โมเดล 8B ในเครื่อง "ใกล้เกณฑ์แต่ไม่ถึง" (ชุดแรกขาดหนึ่งเคส ชุดที่สองไม่ผ่าน ชุดที่สามผ่านที่ขอบ ชุดที่สี่ไม่ทำซ้ำผลนั้น) และยังไม่เคยรันกับโมเดลที่เก่งเลย จึงยังพูดไม่ได้ว่า RCT-7 ช่วยให้โมเดลที่เก่งทำงานได้ดีขึ้น; ส่วนเส้นทาง contract ของอีกฝ่าย (typed intent, เงื่อนไขจำเป็น, ตัวตรวจ citation) ยังแยกจาก loop หลักและยังไม่รวมเป็นแผนเดียว. ตรวจครั้งก่อนหลังรอบที่ 97: ทุกขั้น R1–R7 ตอนนี้ "ทำได้บางส่วน" ไม่มีขั้นไหนครบตามนิยาม ส่วนที่ทำแล้วอ่านจากถ้อยคำของคำขอเองด้วยกฎ ไม่ใช้โมเดล: รู้ว่าไฟล์ที่สั่งให้อ่านไม่มีอยู่เลย, ประโยคที่อ้างถึงสิ่งที่ไม่มี, ข้อกำหนด 7 ชนิด (ภาษา, JSON, ไฟล์ที่ต้องบันทึก, ไฟล์ที่ห้ามแก้, จำนวนคำ, จำนวนตัวอักษร, จำนวนข้อ), ขั้นตอนที่ผู้ใช้เขียนแยกไว้เอง, แผนและเงื่อนไขที่แสดงก่อนใช้เครื่องมือตัวแรก, การหยุดถาม-รอ-ตอบ โดยคำตอบแนบกับคำขอเดิมหนึ่งครั้ง ส่วนที่ต้องใช้โมเดลที่เก่งพอและชุดทดสอบอิสระ (เจตนาคลุมเครือทั่วไป, สิ่งที่ไม่รู้ที่ถ้อยคำไม่บอก, ห่วงโซ่ย้อนกลับพร้อมหลักฐาน) ยังไม่ได้ทำ การหยุดถามเปิดอยู่เฉพาะที่มีคนอยู่หน้าจอ (Desk และแชท) และปิดสำหรับงานตั้งเวลา/job/webhook/API (`DELENTIA_ASK_AND_WAIT=1` เปิดทุกที่ `=off` ปิดทุกที่) ตัวเลขที่วัดมาจากเคสที่ผู้เขียนกฎเขียนเอง จึงเป็นเกราะกันถดถอย ไม่ใช่หลักฐานอิสระ
