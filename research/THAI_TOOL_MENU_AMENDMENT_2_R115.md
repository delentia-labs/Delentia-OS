# Thai tool menu, Amendment 2 (2026-11-16): the result of T1 on the holdout, and the criteria for candidate E1 (written before E1 was run)

## 1. T1 on the holdout (run once, frozen table, `research/results_round115/THAI_TABLE_T1_RESULT.md`)
Holdout: 89 sentences the Architect ticked of 120 new ones, 30 situations. All needed tools in the menu: today 0.0%, **T1 66.3%** (literal wording 95.2%, synonym 68.8%, indirect 30.0%); the development set gave 67.2%, so the table generalised as well as it fitted. Gain +66.3 points (needed 40), mean menu +1.6 tools (allowed 3), guards unchanged. **Two rules failed: the share is below 70% (66.3%), and on the second negative set T1 pulls 1.65 external tools into a menu of a Thai request that needs none (allowed 1; today 0.4).** By the pre-registered rule T1 is **not proposed for adoption**. The table is not changed after seeing this; any better table is a new candidate with a new holdout.

## 2. Why the table fails (read after the run; not used to change T1)
* 14 of the 30 holdout misses are indirect sentences and 15 are synonym sentences with no domain noun ('ปิดงาน 310', 'บ่ายวันจันทร์ฉันว่างอยู่หรือเปล่า', 'นิดาเคยส่งใบเสนอราคามาไหมนะ'): no noun names a server, so a word table adds nothing. This needs meaning, not words.
* The false positives come from the nouns themselves ('โฟลเดอร์', 'ปฏิทิน', 'จดบันทึก' appear in requests about files, articles and the lunar calendar).

## 3. Candidate E1 (embedding add-on), criteria fixed now
Idea: use the multilingual embedding model that is already installed for memory recall (bge-m3, reads Thai) to bring in the tools whose name and description are closest in meaning to a Thai request, in addition to today's lexical menu.
* **Rule.** For a request that contains a Thai character and only when the embedding service answers: menu = today's lexical menu plus the `m` external tools (tools named `mcp__...`) with the highest cosine between the request and the tool text ('name words. description'), each kept only if its cosine is at least `tau`. Tool vectors are computed once per process. English requests, and any request when the embedding service is not available, are scored exactly as today (fail open, nothing added). Switch `DELENTIA_TOOL_MENU_EMBED=on`, default off.
* **Parameters chosen on the DEVELOPMENT sentences only** (the 119 first-form sentences and the first negative set): a grid m in {3, 4, 5, 6} and tau in {0.30, 0.35, 0.40, 0.45, 0.50}; the choice is the setting with the highest share of development sentences having every needed tool in the menu, among settings whose mean number of external tools for the first negative set is at most 1; ties go to the smaller m and then the larger tau. The chosen setting is committed before the holdout is run.
* **Holdout:** the 89 sentences above, run ONCE with the chosen setting. They were seen by T1's evaluation and I read the list of T1's misses; no E1 parameter was chosen from them, and that is the only protection, so the result is reported with this limit.
* **Adoption rule (all):** (1) holdout share with every needed tool in the menu at least 70% and at least 40 points above today's; (2) mean menu growth at most 3 tools; (3) on the second negative set (`tool_menu_thai_negatives2_r115.json`) at most 1 external tool per request on average; (4) the guards (44 English external goals, built-in dev and holdout) lose at most 1 point; (5) the median extra time per Thai request, with the tool vectors cached, at most 150 ms; (6) with the embedding service stopped, the menu equals today's menu for every request in all sets.
* **Reported whatever the result:** per-wording split, the misses, the time, and the limit that the sentences were written by the assistant and nothing was run with a model.
* If E1 passes it is also not turned on by default by me: that is the Architect's decision (it makes the menu depend on a local model).
