# First run, part 3: the slowness, the breaker, the Desk command, the installer in Thai (Round 112C, 2026-11-08)

Source: the four open items I listed after part 2 and the Architect asked to close before any new tag. Written and committed BEFORE the code.

## What was measured before writing the rules (facts)
- On this Windows machine a REFUSED connection to a closed loopback port takes **2.05 s** (plain socket, urllib and httpx alike; `localhost` takes 4.08 s: IPv6 first, then IPv4). That is the operating system, not Delentia's code, and it is why a computer with no Ollama felt slow.
- Where the cold first question spent its time (profile of the real governed loop, no model program): 2.0 s in the memory-recall availability probe (`memory_embeddings._installed_models`, a request to Ollama's model list, timeout 2.0 s, answer cached for 300 s) and about 0.4 s in the model call; a second question in the same process still took 2.15 s. First request to a FRESH `delentia serve` (installed wheel, CI check): 8.2 s; second: 2.3 s.
- Once a request has started, the circuit breaker counts every refused connection as a failure of the model endpoint: after five requests it answers "circuit open", although nothing is wrong with the endpoint except that no program listens.

## Rules (each is a test or a CI step; a rule that is not met is reported, never relaxed afterwards)
- **R13 Warm start.** `delentia serve` warms the path a first question needs (the tool server, the loop factory, the token counter, the TLS context, the recall probe) in a background thread, and `/health` says when it is done (`warm: true`). Test on the installed-wheel check: after `warm` is true, the FIRST agent request to a server with no model program answers within 5 s on CI (it was 8.2 s); on this machine it is reported next to the number. Off with `DELENTIA_WARM_START=0`; tests that open a server do not warm unless asked.
- **R14 The breaker does not punish a program that is simply not there.** A refused (or locally timed-out) connection to this computer is not counted as a failure of the endpoint: ten requests in a row to a closed local port never produce "circuit open". Failures of any other kind, and of any other host, are counted as before (five open it).
- **R15 `delentia desk` finds the agent `delentia launch` chose.** Without `--gateway`, `delentia desk` reads the ports the launcher recorded (`run/ports.json`) and uses that agent if it answers as Delentia; with nothing recorded it uses 8000 as before; an explicit `--gateway` always wins.
- **R16 The installer speaks Thai too.** The package-install caption and the line under it carry a Thai sentence next to the English one, written through a UTF-8-with-byte-order-mark include (the way the stage label already travels), never on the compiler's command line. Test: the build script writes the include and the Thai text matches the English meaning point for point (not a number of minutes, not a percentage). Whether it renders correctly on screen is judged on the Architect's second computer.
- **R17 A short connect timeout for this computer.** A connection to a loopback address that is not accepted within 0.75 s (default; `DELENTIA_LOCAL_CONNECT_TIMEOUT_S`) is given up on, for the model call, the recall probe and the readiness probe; a program that is listening accepts in milliseconds, so this changes nothing for a working Ollama. A loopback connect timeout is classified like a refusal ("not running"). Measured rule: a no-model question in a warm process ends within 1.5 s on this machine (it took 2.15-2.7 s).

## Not claimed
Nothing here makes a model answer faster; it only removes waiting for something that is not there. The first question after the program starts may still pay for imports that the warm thread has not finished (R13 measures after `warm`). The Thai text and the animated bar are judged by a person on screen.
