# Thai tool menu, Amendment 3 (2026-11-16): candidate A1, Thai hints for every external tool (criteria written before any hint was generated or scored)

## 1. Why this candidate
T1 (a request word table) and E1 (cosine to the English description) failed on the holdout (66.3% and 44.9% against a 70% bar; Amendment 2 and `results_round115/`). 29 of 30 T1 misses have no domain noun in the request, so no request-side table can serve them. The built-in tools already carry hints in both languages (`tool_menu.HINTS`, 'english | thai') and are ranked by overlap with them; external tools have none. A1 gives each external tool its own Thai hint, so ranking does not depend on guessing nouns in the request.

## 2. The mechanism (what is built)
* **Where a hint lives:** `~/.delentia/tool_hints_th.json` (or `DELENTIA_TOOL_HINTS_TH`), a plain JSON object `{"<tool name>": {"hint": "<thai words>", "for": "<sha256 of name + description>", "source": "model|owner"}}`. The owner can read and edit it. A hint whose `for` no longer matches the tool's current name and description is ignored (a changed tool must be regenerated or re-approved).
* **How it is used:** for a tool with no built-in hint, the Thai trigrams of its hint are added to the tool's Thai side exactly as a built-in tool's Thai hint is (the existing scoring weight; nothing new is tuned). Switch `DELENTIA_TOOL_MENU_THAI_HINTS=on`, default off. A request with no Thai character is scored exactly as today (a test pins this); with no hints file, or with it off, the menu equals today's menu (a test pins this).
* **How it is produced (generator):** one call per tool to a local model, at connection time or by the owner on demand, from the tool's name and description ONLY. The prompt is frozen in the code before the first run and is not changed after the holdout form is filled in. A hint is 8 to 14 Thai words or short phrases of at least three letters (shorter words produce no trigram), everyday and colloquial forms and synonyms for the action and for what it works on. The generator never sees any request sentence. If the model is unavailable, no hint is written and the menu is today's.

## 3. What is measured, and the roles of the data
* **Hints used in the measurement:** generated by `qwen3:8b` (thinking off, temperature 0) for the 17 synthetic tools, written to `research/tool_hints_th_synthetic_r115.json` and committed BEFORE the third form is built. They are not edited by hand. An upper bound with hints written by hand by the assistant is reported as a second row only for information and never decides adoption (it measures the ceiling of the mechanism, not what a model produces).
* **Development:** the 119 first-form sentences and the first negative set. They may be used to look at failures and to change the PROMPT once; any such change is committed with its reason before the hints are regenerated.
* **Holdout (third form):** 30 NEW situations and 120 NEW sentences, written after the hints and the prompt are committed, filled in by the Architect, run once. The second form (89 ticked sentences) was used by T1 and E1 and is reported for A1 as a second look, not as the decision.
* **Negatives:** a THIRD set of 20 Thai requests that need no external tool, written now, before any hint exists (`tool_menu_thai_negatives3_r115.json`). Guards: the 44 English external goals and the built-in dev and holdout sets.

## 4. Adoption rule (all must hold on the third form and the guards; otherwise A1 is not proposed)
1. The share of sentences with every needed tool in the menu is at least **70%** and at least **40 points** above today's.
2. The mean menu grows by at most **3** tools.
3. On the third negative set the mean number of external tools in the menu is at most **1**.
4. The guards lose at most **1 point**.
5. With the switch off, with no hints file, and with a hint whose `for` does not match, the menu equals today's for every request in all sets (tests).
6. Generation time: at most **60 s per tool** on this machine with `qwen3:8b` (it runs once per tool, not per request).

## 5. Reported whatever the result
Per-wording split; every sentence that still misses a needed tool; the generated hints themselves (they are data); the second-form result; the upper bound with hand-written hints; the limits: sentences written by the assistant, synthetic tools with short English descriptions, one local model generating the hints, and nothing run with a hosted model. If A1 passes, turning it on by default stays the Architect's decision, and a hint file for a real external server must be read by the owner once (a model-written hint is data the model chose).
