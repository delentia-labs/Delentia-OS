# Gate properties and threat map

Generated by `python research/gate_properties.py` from `research/gate_properties.py`; `--check` fails if this file is stale or a named test is gone. Protocol references: section 13 (properties), section 12 (threats).

A property is judged from the **executor** (what the recording tools were asked to run) and the database, not from the gate's own log. It is a statement about the restricted dispatch this runtime knows, under the assumptions listed. It says nothing about a language model, root compromise, a stolen approver key or a person who approves a harmful payload.

## Properties

### P1 - A = 0 blocks restricted effects

When authorization is zero (a denied command, an unsafe path, a tool the owner never registered, a broken policy file, no trusted approver), the tool does not reach the executor. Writes and patches wait for a person even when the path looks safe.

- **Assumes:** The tool server is reached only through the loop's dispatch (P6). The built-in floor treats most tools as A = 1 unless the owner writes a policy; the zero-trust claim holds WITH a policy file.
- **Not covered:** Without an owner policy a restricted tool that is not a write is judged by F >= threshold alone (D and I), not by a signature. That is the design; say so when describing the default.
- **Pinned by:**

  - `test_gate_properties_round65_real.py::test_p1_a_safe_looking_write_still_waits_for_a_person`
  - `test_gate_properties_round65_real.py::test_p1_with_no_trusted_approver_nothing_can_ever_be_approved`

  - `test_fdia_policy_loop_round54_real.py::test_a_broken_policy_file_refuses_every_tool_including_reads`

### P2 - An invalid signature blocks

A flipped bit, non-hex text, an empty signature, a signature for the other decision, for another action, or from an untrusted key never approves; the one genuine signature still does. The agent cannot generate a key that counts.

- **Assumes:** The trusted-approver list is configured outside the agent's reach (environment or a host file).
- **Not covered:** A stolen approver key, or a person who signs a harmful payload (Protocol 12).
- **Pinned by:**
  - `test_gate_properties_round65_real.py::test_p2_signatures_that_do_not_belong_to_this_exact_action_never_approve`
  - `test_gate_properties_round65_real.py::test_p2_the_agent_cannot_sign_for_itself`
  - `test_signed_approval_resume_real.py::test_untrusted_key_is_rejected`

### P3 - A signature does not lift a forbidden path or a refused role

An approved write to .env, a key file or outside the repository still does not run; a key without the required role cannot approve; the owner's denied paths hold after approval.

- **Assumes:** Roles come from the approvers file, not from the request.

### P4 - Expiry and revocation are enforced

A request nobody decided in 7 days cannot be approved; an approval not used in 24 hours never runs (both windows configurable, 0 = off, a bad value never means forever); removing an approver key voids what it signed and has not run, including one of two required signatures. Expired rows stay on disk.

- **Assumes:** The clock of the host is right. Before Round 65 an approval never expired (found by writing this property).
- **Not covered:** An action already running when its key is revoked finishes.
- **Pinned by:**

### P5 - An old approval is void for a changed payload

Changing the arguments, goal, tool or namespace of a stored action after it was approved makes it unrunnable; one approval cannot be replayed on an identical second request or run twice.

- **Assumes:** The digest is recomputed at execution from the stored fields.
- **Not covered:** Someone who can rewrite both the row and re-sign with a trusted key.
- **Pinned by:**

### P6 - Every entrant path uses the gate

Only four code sites hand a call to the tool server (the single-call path, the batch path, warm replay of read-only evidence, and resume after claim); a batch is held whole when one call needs a signature; no module builds an ungoverned loop.

- **Assumes:** Static check of the two loop modules; an external process that talks to the tool server directly (the raw /mcp gateway) is the owner's route and is covered by the route test.
- **Not covered:** No model checking of the approval flow as a state machine (Protocol 13 suggests it; not done).
- **Pinned by:**
  - `test_gate_properties_round65_real.py::test_p6_only_the_known_choke_points_call_a_tool`
  - `test_gate_properties_round65_real.py::test_p6_a_batch_is_gated_call_by_call_before_any_of_it_runs`

### P7 - A required notary that fails closes the gate

With a notary configured and unreachable, the tool does not run (stopped_reason notary_unavailable) and an approved action is not consumed.

- **Assumes:** DELENTIA_NOTARY_URL is set; without it nothing changes (and nothing is claimed).
- **Pinned by:**

### P8 - Nothing is learned from an invalid outcome

An episode that was held, refused, errored, declined, or that read text from outside produces no skill; a clean verified episode still does. (Before Round 65 an episode that read a page could become a skill carrying the page's text.)

- **Assumes:** The taint gate is on (DELENTIA_TAINT_GATE default).
- **Not covered:** Warm-recall answers cached from a tainted episode are replayed only if their read-only evidence is identical; not changed.
- **Pinned by:**
  - `test_gate_properties_round65_real.py::test_p8_an_episode_that_did_not_succeed_teaches_nothing`
  - `test_gate_properties_round65_real.py::test_p8_an_episode_that_read_outside_text_does_not_become_a_skill`
  - `test_gate_properties_round65_real.py::test_p8_control_a_clean_verified_episode_is_still_learned`

### P9 - A revoked memory is never used again

After `revoke_memory` no reader returns it (recall, scored recall, listings, the Desk page); the row and text stay on disk and the revocation is in the audit trail; one person cannot revoke another's; old databases are migrated.

- **Assumes:** Every reader goes through ControlPlanePersistence.list_memories (the only SQL reader of the table besides the Desk page, which filters too).
- **Not covered:** A skill derived from a memory is not revoked with it; nothing is erased (PDPA erasure needs a separate, per-subject key design).
- **Pinned by:**
  - `test_gate_properties_round65_real.py::test_p9_a_revoked_memory_is_returned_by_nothing`
  - `test_gate_properties_round65_real.py::test_p9_revoking_is_scoped_to_the_owner_and_happens_once`
  - `test_gate_properties_round65_real.py::test_p9_an_older_database_gets_the_new_columns_and_keeps_its_memories`
  - `test_gate_properties_round65_real.py::test_p9_the_recall_tool_the_agent_uses_does_not_return_a_revoked_memory`

### P10 - Cancelling cannot make an action run twice; the emergency stop reaches approved actions

An approved action cancelled mid-run stays claimed and cannot be claimed again; while the agent is paused an already approved action does not run and is not consumed.

- **Not covered:** A tool already executing in a worker thread cannot be recalled; at-most-once is guaranteed, completion is not.
