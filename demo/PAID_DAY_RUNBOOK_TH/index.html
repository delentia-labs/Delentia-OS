    วันทดสอบกับโมเดลจริง: คู่มือทีละขั้น (OpenRouter จ่ายล่วงหน้า $15)¶

    สำหรับเจ้าของระบบ ทำใน PowerShell ของตัวเอง (ไม่ใช่หน้าต่างที่ Claude ใช้) ห้ามวางคีย์ลงแชต ไฟล์ หรือ commit คีย์อยู่ในหน่วยความจำของหน้าต่างเดียวและหายเมื่อปิดหน้าต่าง

    เอกสารนี้ใช้ตัวขับ scripts/paid_day.py ที่คุมทั้งวันให้อยู่ในเพดานเดียวกัน และซ้อมมาแล้วกับ OpenRouter ปลอมที่คิดเงินในตัวนับของมันเอง (ไม่เสียเงิน) คู่มือเก่า OPENROUTER_KEY_AND_CAP_TH.md อธิบายแต่ละขั้นแบบทำมือ ใช้เป็นคำอธิบายประกอบ

    สถานะตามจริง: ทุกขั้นซ้อมผ่านกับตัวปลอม (ตัวนับของเรา = ตัวนับของเซิร์ฟเวอร์ปลอม ถึงสตางค์) ยังไม่เคยรันกับ OpenRouter จริง สิ่งที่การรันจริงบอกได้คือโมเดลจริงทำอะไร ซึ่งสคริปต์บอกไม่ได้

    เงินแบ่งอย่างไร¶

    ขั้น ตอบคำถามอะไร เพดาน
    P0 ตัวนับเงินของเราตรงกับตัวเลขของผู้ให้บริการหรือไม่ (ต้องผ่านก่อนอย่างอื่น) $0.10
    P1 โมเดลไหนใน 22 ตัว ขับ loop ที่มีธรรมาภิบาลได้ (T1, T2 ≥ 90%, T3 = 100%) $5.00
    P1b เมนูเครื่องมือย่อ vs เมนูเต็ม (เฉพาะโมเดลที่ผ่าน P1 ไม่เกิน 3) $1.50
    P2 judge / critic / context judge ผ่านกฎของตัวเองบนชุดที่คุณลงป้ายไว้ $1.50
    P4 งานเดียวกันให้ผลต่างกันหรือไม่เมื่อมีและไม่มี runtime (TC-003, TC-006) $4.00
    PR โมเดลที่ดูภาพได้อ่านวิดีโออ้างอิงแล้วเขียนแผนได้หรือไม่ และข้อความ RCT-7 เปลี่ยนแผนหรือไม่ (เชิงบรรยาย ไม่เกิน 2 โมเดล) $0.75
    รวมเพดาน $12.85

    $15 − \(12.85 = **\)2.15** เป็นเงินสำรองที่คีย์เข้าไม่ถึง (ตั้ง credit limit ของคีย์ไว้ที่ 12.85) ใช้จริงคาดว่าน้อยกว่านี้มาก

    ก่อนวันรัน (ทำได้เลย ไม่ต้องมีคีย์)¶

    1. ที่ OpenRouter เติมเครดิตจ่ายล่วงหน้า $15 ครั้งเดียว และ ปิด auto top-up (Settings → Credits) บัตรมีค่าธรรมเนียมราว 5.5% (ขั้นต่ำ $0.80)
    2. เพิกถอนคีย์เก่าที่เคยรั่ว (Keys → Delete) ถ้ายังไม่ได้ทำ
    3. สร้างคีย์ใหม่ชื่อ delentia-prepaid-2026-10 ตั้ง Credit limit = 12.85 คัดลอกครั้งเดียว
    4. ที่ C:\Users\whale\Delentia\Delentia-OS: git pull แล้ว git status ต้องสะอาด (freeze ปฏิเสธโฟลเดอร์ที่มีการแก้ค้าง)
    5. ใช้ py -3.13 ทุกคำสั่ง

    ขั้นที่ 1: ตั้งค่าในหน้าต่างเดียว¶

    $k = Read-Host "OpenRouter key" -AsSecureString
$env:OPENROUTER_API_KEY = [System.Net.NetworkCredential]::new('', $k).Password
$env:DELENTIA_RUN_LIVE_TESTS = "1"
$env:DELENTIA_OPENROUTER_DATA_COLLECTION = "deny"
$env:DELENTIA_OPENROUTER_REQUIRE_PARAMETERS = "1"
cd C:\Users\whale\Delentia\Delentia-OS
New-Item -ItemType Directory -Force $env:USERPROFILE\daaes-results | Out-Null
$m = (Get-Content research/screen_models_2026-10-31.txt) -join ","

    ใช้หน้าต่างนี้ต่อทุกขั้น freeze บันทึกค่าเหล่านี้ไว้ หน้าต่างที่ตั้งต่างกันจะถูกปฏิเสธ โมเดลที่ไม่มีผู้ให้บริการภายใต้ deny จะเรียกไม่สำเร็จ นั่นถูกต้อง (บันทึกเป็น not_run)

    ขั้นที่ 2: freeze สิ่งที่จะวัด¶

    py -3.13 -m research.paid_run_freeze write --models $m --live-prices --stages P0,P1,P1b,P2,P4,PR --budget-usd 12.85 --provider-cap-confirmed --out $env:USERPROFILE\daaes-results\freeze.json
$env:DELENTIA_FREEZE_FILE = "$env:USERPROFILE\daaes-results\freeze.json"
py -3.13 -m research.paid_run_freeze check $env:DELENTIA_FREEZE_FILE

    ใส่ --provider-cap-confirmed เฉพาะเมื่อทำข้อ 3 ของ "ก่อนวันรัน" แล้ว check ต้องพิมพ์ว่าตรงกับ freeze ถ้าราคาเปลี่ยนระหว่างวัน มันจะบอกว่าอะไรต่างและไม่ส่งอะไร

    ขั้นที่ 3: ตรวจก่อนใช้เงิน (ไม่เสียเงิน)¶

    py -3.13 scripts/paid_day.py preflight --models $m --freeze-file $env:DELENTIA_FREEZE_FILE

    ทุกบรรทัดต้องเป็น OK มันเช็ก: คีย์ตั้งแล้ว, เปิด live tests, ปิดการเก็บข้อมูลที่ปลายทาง, freeze ตรง, คีย์มี credit limit ที่ผู้ให้บริการและไม่เกิน $12.85, ยอดคงเหลือพอสำหรับขั้นที่จะรัน, ราคาทุกโมเดลรู้, ชุด RCT-7 ทั้งสี่มีไฟล์ปิดผนึก บรรทัดที่เป็น NO คือสิ่งที่ต้องแก้ก่อน ไม่ต้องเดา

    ขั้นที่ 4: ขั้น 1 (P0 + P1)¶

    ดูแผนก่อน (ไม่ใส่ --execute = ไม่ส่งอะไร ไม่เสียเงิน):

    py -3.13 scripts/paid_day.py stage1 --models $m --freeze-file $env:DELENTIA_FREEZE_FILE

    แล้วรันจริง:

    py -3.13 scripts/paid_day.py stage1 --models $m --freeze-file $env:DELENTIA_FREEZE_FILE --execute

    ลำดับ: P0 กับโมเดลที่ถูกที่สุด (ถ้าไม่ผ่าน หยุดทั้งวัน ส่ง p0.json ให้ผม) แล้ว P1 กับทุกโมเดล ตัวขับตรวจยอดใช้จริงจากตัวเลขของผู้ให้บริการ (ไม่ใช่ตัวนับของเรา) หลังทุกคำสั่ง และหยุดเมื่อเกินเพดานของขั้น ใช้เวลาไม่นาน ผลอยู่ใน %USERPROFILE%\.delentia\paid-day\<วันที่>\ (หรือ --out-dir)

    เมื่อจบ มันพิมพ์รายชื่อโมเดลที่ ผ่านกฎ (T1, T2 ≥ 90%, T3 = 100% ตัวเลขหายนับว่า inconclusive ไม่ใช่ผ่าน) พร้อมข้อเสนอไม่เกิน 3 ตัวจากต่างค่าย เลือกจากรายการนั้นเท่านั้น ถ้าไม่มีโมเดลไหนผ่าน นั่นคือผลที่บันทึกตามจริง และขั้น 2 ไม่ต้องรัน (เงินที่เหลือยังอยู่ครบ)

    ขั้นที่ 5: ขั้น 2 (P1b + P2 + P4) กับโมเดลที่เลือก¶

    py -3.13 scripts/paid_day.py stage2 --selected "<id1>,<id2>,<id3>" --freeze-file $env:DELENTIA_FREEZE_FILE
py -3.13 scripts/paid_day.py stage2 --selected "<id1>,<id2>,<id3>" --freeze-file $env:DELENTIA_FREEZE_FILE --execute

    มันบันทึก selection.json ก่อน เริ่ม (เพื่อให้เห็นว่าเลือกอะไร ก่อนเห็นผล) ปฏิเสธมากกว่า 3 โมเดล และรัน P1b (A/B เมนู), P2 (ชุด RCT-7 สี่ชุด: แต่ละ prompt+ป้ายรันได้ครั้งเดียวต่อโมเดล) และ P4 (TC-003 แขน b0/d0 เมล็ด 1700-1703 กับ TC-006) โมเดลที่แพงจนขั้นหนึ่งไม่พอดีเพดานจะถูกข้าม พร้อมเหตุผลในล็อก

    ขั้นที่ 5b: ขั้น 3 (PR) อ่านวิดีโออ้างอิงแล้วทำแผน ด้วยโมเดลที่ดูภาพได้¶

    ขั้นนี้ให้โมเดลที่รับภาพได้อ่านวิดีโออ้างอิงสังเคราะห์ (ภาพนิ่งหกภาพ วิดีโอสร้างบนเครื่องคุณและรู้เฉลยอยู่แล้ว) แล้วเขียนแผนการผลิต สามแบบ: แบบธรรมดา, แบบใส่ข้อความแผนที่ runtime ใช้อยู่วันนี้ และแบบใช้ขั้น RCT-7 ทั้งเจ็ดเป็นลำดับการคิด กติกาอยู่ใน research/PREPAID_CRITERIA_R103.md หัวข้อ PR ซึ่งเขียนไว้ก่อนมีโมเดลใดรัน ราคาถูก (ราว $0.07 ถึง $0.50 ต่อโมเดล) ใช้ไม่เกินสองโมเดล และจะรันการตรวจตัววิเคราะห์ฟรีก่อน: ถ้าเครื่องมือของเราวัดวิดีโอผิดเอง จะไม่ส่งอะไรให้โมเดลเลย

    py -3.13 scripts/paid_day.py stage3 --vision-models "<id1>[,<id2>]" --freeze-file $env:DELENTIA_FREEZE_FILE
py -3.13 scripts/paid_day.py stage3 --vision-models "<id1>[,<id2>]" --freeze-file $env:DELENTIA_FREEZE_FILE --execute

    ตัวตรวจก่อนเริ่มปฏิเสธโมเดลที่รายการของผู้ให้บริการเองไม่ได้บอกว่ารับภาพ, เกินสองโมเดล, และตัวเลือกที่ประมาณการรวมส่วนเผื่อ 1.5 เท่าแล้วไม่พอดีเพดาน $0.75 (โมเดลแพงสองตัวไม่พอดี) มันเขียน selection_pr.json ก่อนใช้เงิน

    ทางเลือก ไม่มีการให้คะแนน: เติม --your-clip "C:\path\to\คลิปที่คุณเป็นเจ้าของ.mp4" --allow-your-clip-frames ในคำสั่ง --execute ระบบจะส่งภาพคีย์เฟรมของคลิป ของคุณ ไม่เกิน 12 ภาพให้โมเดลตัวแรก และคุณได้รายงานไว้อ่าน ภาพเหล่านี้ออกจากเครื่องคุณ: ใช้เฉพาะคลิปที่คุณเป็นเจ้าของ และไม่ใช้คลิปที่มีคนที่ไม่ได้ยินยอม

    ฟรี ไม่ใช้โมเดล ทำเมื่อไรก็ได้: py -3.13 -m research.reference_stage analyze --video "C:\path\clip.mp4" --out $env:USERPROFILE\daaes-results\myclip วัดคลิป (ความยาว ขนาด เสียง รอยตัดอยู่ตรงไหน ภาพคีย์เฟรมต่อช็อต) และไม่ส่งอะไรออกไปที่ใด

    ขั้นที่ 6: สรุป และส่งผลให้ผมบันทึก¶

    py -3.13 scripts/paid_day.py summary

    ได้ตารางต่อขั้น: จำนวนคำสั่ง, exit code, ยอดใช้สูงสุดเทียบเพดาน, และรายการที่ถูกปฏิเสธ จากนั้น:

    1. เทียบยอดกับ openrouter.ai → Activity
    2. ส่งโฟลเดอร์ผลให้ผม ไม่มีคีย์ในไฟล์ใด (มีการทดสอบว่าไม่มีคีย์ในไฟล์ผลของการซ้อม) ผมจะอ่านผลทีละไฟล์ ให้ verdict ตามกฎของแต่ละขั้น (pass / fail / inconclusive / not_run) และลง research/RESULTS_REGISTER.jsonl พร้อมต้นทุนจริงและการตั้งค่า การรันที่ไม่มีต้นทุนจริงบันทึกไม่ได้
    3. ปิดหน้าต่าง PowerShell ถ้าไม่ใช้ต่อ ให้ลบคีย์ที่ OpenRouter

    ถ้าเกิดอะไรขึ้น¶

    อาการ ความหมาย ทำอะไร
    Refused: ... NO preflight ไม่ผ่านบรรทัดนั้น แก้บรรทัดนั้น ยังไม่เสียเงินเลย
    STOPPED: ... เกินเพดาน ขั้นนั้นใช้เกินเพดานที่กำหนด ห้ามรันซ้ำ ส่งล็อกมาให้ผมก่อน
    P0 FAIL ตัวนับของเรากับของผู้ให้บริการต่างเกิน 10% หยุดทั้งวัน ส่ง p0.json
    P0 INCONCLUSIVE ยอดของผู้ให้บริการยังขยับ รันซ้ำครั้งเดียว
    โมเดลหนึ่งไม่มี endpoint ภายใต้ deny ผู้ให้บริการไม่มีเงื่อนไขที่ขอ ถูกต้อง: not_run ไม่ใช่ความผิดพลาด
    เครดิตหมด/401/402 บัญชีปฏิเสธ ตัวขับหยุดเอง ไม่ลองซ้ำ

    ผลนี้พิสูจน์และไม่พิสูจน์อะไร¶

    ผ่าน P1 บอกว่าโมเดลเลือก tool ถูกและปฏิเสธเป้าหมายที่ทำไม่ได้ในงานสั้น ไม่ได้บอกว่าตัวไหนทำงานจริงได้ดีกว่า และไม่ได้บอกว่า Delentia ทำให้ดีขึ้น: นั่นคือ P4 ซึ่งมีสี่รอบต่อแขน เป็นการบรรยาย ไม่ใช่ข้อค้นพบ ไม่อ้างว่าดีขึ้นเว้นแต่ช่วงความเชื่อมั่นไม่คร่อมศูนย์ และอ้างได้เฉพาะโมเดลนั้นกับงานนั้น มันไม่ซื้อ: การเทียบกับ Hermes, การทำงานอัตโนมัติหลายวัน, host หรือผู้ใช้ภายนอก ผลที่ออกมาไม่ว่าอย่างไร (รวมผลที่ไม่ดี) จะถูกบันทึกและเผยแพร่ตามที่เป็น พร้อมวิธี โมเดล ต้นทุน และข้อจำกัด
