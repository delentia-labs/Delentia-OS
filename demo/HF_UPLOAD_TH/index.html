    คู่มือ: แก้การ์ดโมเดลบน Hugging Face ให้ตรงกับหลักฐาน (14 การ์ด) ทำเองด้วยโทเค็นของคุณ¶

    สำหรับเจ้าของระบบ (Architect) ใช้เวลาประมาณ 20 นาที เครื่องมือ Hugging Face ฝั่งผมอ่านได้อย่างเดียว ผมจึงอัปโหลดให้ไม่ได้ และไม่ควรได้ถือโทเค็นเขียนของคุณ

    0. ทำไมต้องแก้¶

    ผมสแกนการ์ดสาธารณะ 23 ใบของ org Delentia (บันทึก: hf_card_scan_2026-10-19.txt ที่รากของ workspace) พบ 17 ใบมีถ้อยคำที่เกินหลักฐาน เช่น "peer-reviewed", "Certified", "production-ready", "mathematically impossible", "ZK-FDIA", อัตราหลอน 0.00%, ตัวเลข 4,849 เทสต์ที่ถอนแล้ว และเวลาสลับ adapter "0.0000 ms" ตัวเลขเหล่านี้มาจากสคริปต์ที่เขียนเอง (self-reported) ไม่ผ่านการทบทวนโดยผู้อื่น และการ์ด v0.4 อ้างอัตราหลอน 0.00% ทั้งที่เมื่อผมทดสอบโมเดลนี้เองได้ 1 จาก 10 ข้อ (คำถามกฎหมาย) และ 0 จาก 5 ข้อ (เป้าหมายง่ายผ่านระบบ) ถ้านักวิจัยหรือนักข่าวเอาตัวเลขเหล่านี้ไปเทียบ ความน่าเชื่อถือของ ทั้งโครงการ จะเสีย

    สิ่งที่ผมเตรียมให้ (ไม่ได้แตะ HF เลย): ฉบับแก้ของการ์ด v0.4 หลัก (HF_README_v04_CORRECTED_2026-10-19.md) และแบนเนอร์สถานะสำหรับอีก 13 repo (โฟลเดอร์ hf_cards_corrected_2026-10-19/) พร้อมไฟล์ต้นฉบับ *.ORIGINAL.md ทุกใบไว้ย้อนกลับ

    หลักการแก้: ไม่ลบประวัติและไม่ลบน้ำหนักโมเดล ใส่แบนเนอร์บอกสถานะจริงบนสุด ตัดคำที่ยืนยันไม่ได้ และบอกว่าตัวเลขเป็นของผู้เขียนเอง

    1. อ่านฉบับแก้ก่อน (สำคัญที่สุด คุณเป็นเจ้าของถ้อยคำสุดท้าย)¶

    cd C:\Users\whale\Delentia
code HF_README_v04_CORRECTED_2026-10-19.md                  # หรือ notepad
fc HF_README_v04_ORIGINAL_BACKUP_2026-10-19.md HF_README_v04_CORRECTED_2026-10-19.md | more     # ดูว่าเปลี่ยนตรงไหน
    ตรวจให้แน่ใจว่า: (ก) แบนเนอร์บนสุดพูดสิ่งที่คุณยอมรับได้ (ข) ไม่มีประโยคที่คุณไม่อยากให้เป็นข้ออ้างสาธารณะ (ค) ไม่มีสิ่งที่คุณอยากเก็บไว้แต่ผมตัดออก ถ้าไม่เห็นด้วยกับข้อใด แก้ไฟล์เอง หรือบอกผมให้แก้ แล้วค่อยไปข้อถัดไป ห้ามอัปโหลดฉบับที่ยังไม่ได้อ่าน

    2. สร้างโทเค็นเขียน แบบจำกัด อายุสั้น¶

    1. เข้า https://huggingface.co/settings/tokens → Create new token
    2. เลือกชนิด Fine-grained (ไม่ใช่ Write กว้าง)
    3. ใต้ Repositories permissions เพิ่ม repo ของ org Delentia ที่จะแก้ (ทั้ง 14: ชื่ออยู่ในผลของข้อ 4) และติ๊ก Write access to contents/settings of selected repos เท่านั้น
    4. ตั้งชื่อ delentia-cards-oneoff ตั้งวันหมดอายุให้สั้นที่สุด (7 วัน)
    5. สร้างแล้วคัดลอก ครั้งเดียว ห้ามวางลงแชตหรือไฟล์ใด ๆ

    3. ติดตั้งและใส่โทเค็นในหน้าต่างเทอร์มินัลนี้เท่านั้น¶

    py -3.13 -m pip install huggingface_hub
$k = Read-Host "HF write token" -AsSecureString
$env:HF_TOKEN = [System.Net.NetworkCredential]::new('', $k).Password
    (ช่องจะไม่แสดงตัวอักษร; ปิดหน้าต่างเมื่อเสร็จ โทเค็นจะหายจากหน่วยความจำ)

    4. ซ้อมก่อน (ไม่อัปโหลดอะไร)¶

    cd C:\Users\whale\Delentia
py -3.13 scripts/upload_hf_cards_r90.py HF_README_v04_CORRECTED_2026-10-19.md hf_cards_corrected_2026-10-19 --dry-run
    ต้องเห็นบรรทัด would upload ... -> Delentia/<repo> ครบ 14 บรรทัด (v0.4 หลัก + 13) ถ้าจำนวนหรือชื่อไม่ตรงที่คาด หยุดและบอกผม

    5. อัปโหลดจริง¶

    py -3.13 scripts/upload_hf_cards_r90.py HF_README_v04_CORRECTED_2026-10-19.md hf_cards_corrected_2026-10-19
    แต่ละ repo ได้ หนึ่ง commit ที่ README.md ไฟล์เดียว (ไม่แตะน้ำหนัก) ข้อความ commit บอกว่าทำอะไร

    6. ตรวจบนเว็บ¶

    เปิดแต่ละหน้าใน https://huggingface.co/Delentia ดูว่าแบนเนอร์ขึ้นและไม่มีคำที่ถอนแล้ว (ค้นหาในหน้า: peer-reviewed, Certified, 4,849, mathematically impossible) ถ้าหน้าไหนเพี้ยน (ตาราง/ลิงก์พัง) แก้ไขไฟล์ README ในเว็บได้เลย หรือบอกผม

    7. ย้อนกลับถ้าไม่พอใจ¶

    แต่ละการ์ดมีไฟล์ต้นฉบับ (*.ORIGINAL.md และ HF_README_v04_ORIGINAL_BACKUP_2026-10-19.md) อัปโหลดทับด้วยไฟล์นั้น หรือใน HF ไปที่ repo → Files and versions → ดูประวัติ commit แล้วเปิดไฟล์เก่าคัดลอกกลับ ประวัติจะเก็บทุกฉบับ (ไม่มีอะไรหายไป ตามนโยบาย Zero-Delete)

    8. เก็บกวาด¶

    1. ปิดหน้าต่าง PowerShell นั้น
    2. https://huggingface.co/settings/tokens → Revoke โทเค็น delentia-cards-oneoff ทันที (แม้ตั้งวันหมดอายุไว้แล้ว)
    3. บอกผมว่าเสร็จแล้ว ผมจะอัปเดตเอกสารสถานะ (ตัวเลขนับการ์ดที่แก้) และตรวจซ้ำด้วยเครื่องมืออ่านของผม

    9. สิ่งที่ยังไม่ได้ทำ (ซื่อสัตย์)¶

    • การ์ดแก้เป็นร่างของผม คุณยังไม่ได้อนุมัติถ้อยคำละเอียด (ข้อ 1 คือขั้นอนุมัติ)
    • ผมไม่ได้ลบ/ย้ายโมเดลหรือแก้ metadata (license, tags) นอกจาก README; แท็ก peer-reviewed อาจอยู่ใน YAML ส่วนหัวของการ์ด หลังอัปโหลดให้เปิดดูส่วนหัวว่ายังเหลือหรือไม่ ถ้าเหลือบอกผม
    • ผลทดสอบจริงของโมเดลตัวเอง (1/10 และ 0/5) เป็นผลของ เครื่องนี้ + CPU + ตัวอย่างเล็ก ไม่ใช่ข้อสรุปว่าโมเดลใช้ไม่ได้
